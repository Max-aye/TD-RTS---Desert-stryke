## О проекте

**TERRA 2136 — Desert Stryke** — самостоятельная браузерная игра для телефона и компьютера. Игровой runtime собирается в один HTML-файл примерно на 43 МБ: его можно открыть локально и играть офлайн.

Внутри проекта соединены:

- тактический бой в реальном времени в формате tower offense;
- кампания из 50 операций и коллекция из 82 карт;
- штаб, ангар, модули, награды и терминал;
- WebGL2-рендеринг, визуальные модели и эффекты;
- детерминированная симуляция с фиксированным шагом 20 Гц;
- мобильный и desktop-интерфейс с автоматической QA-проверкой.

> **Текущий фокус:** версия `0.95.0` — порядок штаба, единые иконки, читаемость и мобильный UX. Следующий этап — улучшение HUD боя в `0.96.0`.

## Быстрый старт

### Просто поиграть

1. Откройте [`index.html`](./index.html) в браузере.
2. Нажмите **«Запустить операцию»**.
3. Для прямого запуска откройте [готовую сборку `TERRA2136_PLAY_v0.95.0.html`](./TERRA2136_PLAY_v0.95.0.html).

Никаких серверов, аккаунтов, внешних ресурсов или дополнительных установок не требуется. Прогресс хранится локально в браузере.

### Запустить локальный HTTP-сервер (необязательно)

Некоторые браузеры строже относятся к большим локальным HTML-файлам. В таком случае используйте встроенный сервер Python:

```bash
python3 -m http.server 8000
```

После этого откройте <http://localhost:8000/>.

## Архитектура репозитория

Рабочими исходниками является `parts/`. Большой HTML-файл — результат сборки и готовый игровой артефакт.

```text
.
├── index.html                         # аккуратный landing page и точка входа
├── TERRA2136_PLAY_v0.95.0.html        # готовая офлайн-игра
├── parts/                              # исходники, из которых собирается HTML
│   ├── markup/                         # каркас head, меню, боя и модалок
│   ├── css/                            # базовые стили и слой UI-полировки
│   ├── ui/                             # экраны, навигация, HUD и ввод
│   ├── game/                            # симуляция, кампания и прогресс
│   ├── render/                          # WebGL-рендер и визуальные эффекты
│   ├── engine/                          # игровой и визуальный runtime
│   └── data/                            # конфигурация и встроенные ассеты
├── tools/                              # split, build, check и patch
├── qa/                                 # headless QA меню и battle smoke test
├── patches/                            # повторяемые версионные патчи
├── docs/                               # roadmap, changelog, аудит и заметки
├── CLAUDE.md                           # правила разработки и инварианты
└── REWARDS_REVIEW.md                   # отдельный разбор экономики
```

### Как всё работает

`tools/build.py` объединяет части из `parts/` в единый HTML. В браузере `ui/controller.js` связывает экраны и ввод с `TerraSim` из `game/content-sim.js`, а `TerraProgress` из `game/progress.js` отвечает за транзакции кошелька, сохранения и экспорт. Рендеринг и визуальные эффекты находятся в `render/` и `engine/`.

Симуляция отделена от presentation/render-only-слоя: бой использует фиксированный шаг и seed, поэтому визуальные улучшения не должны менять игровой результат.

## Сборка из исходников

**Требования:** Python 3.11+, Node.js 20+ и Git. Для автоматической QA дополнительно нужны Playwright и Chromium.

```bash
# собрать готовую игру
python3 tools/build.py parts/ dist/TERRA2136_PLAY.html

# проверить синтаксис всех <script>-блоков через node --check
python3 tools/check.py dist/TERRA2136_PLAY.html
```

Если исходники ещё не разделены на `parts/`, выполните это один раз:

```bash
python3 tools/split.py TERRA2136_PLAY_v0.95.0.html parts/
```

Для проверки обратной совместимости сборки с исходным HTML:

```bash
python3 tools/build.py parts/ dist/TERRA2136_PLAY.html --verify
```

## QA и проверка интерфейса

Установка Playwright:

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
```

Полный рекомендуемый прогон:

```bash
python3 tools/check.py dist/TERRA2136_PLAY.html
python3 qa/qa.py dist/TERRA2136_PLAY.html --out qa-out --no-battle
python3 qa/qa.py dist/TERRA2136_PLAY.html --out qa-out --battle-only --viewports mobile
```

QA проверяет запуск меню и боя, ошибки страницы и консоли, битые изображения, горизонтальный overflow, размеры touch-target, мелкий текст, стабильность dock и установку постройки. Итоговая строка имеет формат `QA RESULT: PASS|FAIL`; подробности и скриншоты сохраняются в `qa-out/`.

## Принципы разработки

- Правьте `parts/`, а не собранный HTML.
- Одна задача — одна тема; после изменений: `build → check → qa`.
- Новые UI-правила добавляйте в последний слой `css/10-polish95.css`.
- Кошелёк изменяется только через транзакции `TerraProgress`.
- Новые поля сохранения должны быть необязательными и иметь значение по умолчанию.
- Не добавляйте внешние шрифты, CDN, сетевые запросы или незашитые ассеты.
- Номер версии меняется только в `parts/ui/version95.js`, `<title>` и `parts/markup/body.html`.
- Изменения баланса требуют отдельной задачи и записи «было → стало» в [`docs/CHANGELOG.md`](./docs/CHANGELOG.md).

Полная рабочая модель и инварианты описаны в [`CLAUDE.md`](./CLAUDE.md).
