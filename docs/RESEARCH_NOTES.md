# Заметки по работе с Opus 5.5 и Claude Code (сентябрь 2026)

Источники — официальная документация; ниже пересказ того, что повлияло на этот набор.

- Уровень effort по умолчанию у Opus 5.5 — `medium`, и на нём модель не хуже Opus 5 на `high` в задачах по коду. Меньше думать дешевле и быстрее через снижение effort, а не через слова в промте. `xhigh`/`max` — только где измерен выигрыш.
  https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5
- В долгих задачах модель может закончить ход отчётом, не доделав работу. Помогают чек-лист в файле (у нас `docs/TASKS.md`), короткое напоминание об открытых пунктах и стоячая инструкция не останавливаться ради отчёта (наш вариант — в `PROMPTS.md`).
- Для интерфейсов нужно перечислять конкретные запрещённые приёмы; общее «без шаблонного вида» меняет один шаблон на другой.
- Скриншоты модель читает точнее, если у неё есть инструменты обрезки и увеличения — отсюда `qa/qa.py` и совет обрезать участки в навыке `terra-visual-check`.
- Opus 5-поколение само проверяет свою работу; инструкции «перепроверь» только удлиняют ходы. Для ревью лучше просить сообщать всё, а отбирать отдельно (так написан `qa-reviewer`).
  https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5
- `/goal` в Claude Code: после каждого хода маленькая модель читает переписку и решает, выполнено ли условие. Условие должно быть измеримым и доказуемым выводом команд, с ограничением по ходам.
  https://code.claude.com/docs/en/goal
- Субагенты: файлы `.claude/agents/*.md` с полями `name`, `description`, `tools`, `model`, `effort`; вложенность и параллелизм ограничиваются переменными `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` и `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (у нас 1 и 4).
  https://code.claude.com/docs/en/sub-agents
