## Что это за игра

**TERRA 2136 — Desert Stryke** — компактная тактическая стратегия о враждебном марсианском фронтире. Здесь недостаточно просто поставить башню: нужно читать ситуацию, беречь ресурсы, выбирать улучшения и выдерживать давление волн.

Это playable-проект, который можно открыть прямо в браузере, и одновременно техническое портфолио с настоящим игровым циклом:

- бой в реальном времени на стыке **tower defense и RTS**;
- кампании, миссии, карта и долгосрочная прогрессия;
- модули, улучшения, награды и локальное сохранение;
- WebGL2-визуализация и автономная доставка одним HTML-файлом;
- mobile-first интерфейс, рассчитанный не только на desktop;
- автоматизированные проверки меню, touch-target, переполнений и запуска боя.

> **Главная идея:** открыть, сыграть несколько минут, увидеть систему в действии и при желании изучить, ��ак она собрана из исходников в единый офлайн-артефакт.

## Попробуйте за 3 минуты

1. Откройте [`index.html`](./index.html) и перейдите в игру.
2. На экране штаба выберите рекомендованный следующий шаг.
3. Запустите бой, поставьте оборонный модуль и переживите первую угрозу.
4. Вернитесь в штаб, изучите отчёт и подготовьте следующий выход.

Готовая сборка доступна здесь: [`TERRA2136_PLAY_v0.99.0.html`](./TERRA2136_PLAY_v0.99.0.html).

**Ничего устанавливать не нужно:** backend, аккаунт, интернет и внешний CDN не требуются.

## Что уже работает

| Для игрока | Для разработчика |
|---|---|
| Тактический бой с фиксированным шагом симуляции | Разделённые исходники, собираемые в один HTML |
| Штаб, кампании, миссии и развитие карты | Воспроизводимый `split → build → check → QA` pipeline |
| Модули, улучшения, награды и локальный прогресс | WebGL2 render pipeline и встроенные ассеты |
| Адаптивный UI для телефона и desktop | `node --check` для всех скриптов сборки |
| Нижняя навигация с единым набором иконок | Playwright smoke-тесты меню и боя |

### Что изменилось в v0.99.0

Последние обновления — читаемость боя и работа над моделями юнитов:

- в бою не осталось подписей мельче 10 px, цели касания — не меньше 44 px (0.96.0);
- первый бой ведёт по трём шагам: стройка → улучшение → поддержка (0.96.0);
- анизотропная фильтрация поднята с 4× до 8×, подробные модели выбираются по реальному размеру юнита на экране, а не по числу зума (0.97.0);
- корпус техники наклоняется при разгоне и торможении, на уклонах и кренится в поворот (0.97.0–0.97.1);
- текстуры моделей масштабируются под качество устройства: на телефоне 23,4 МБ → 18,8 МБ видеопамяти без потери моделей (0.97.1);
- повтор операции приносит 35 % от первой победы (до 5 повторов в день), находки в бою — 6–12 сплава вместо 3–7 (0.98.0);
- карты «Гренадёр» и «Ракетный» получили свои портреты вместо картинки здания, которое их выпускает (0.98.1);
- техдолг: мёртвые правила стилей удалены, тридцать шесть таблиц наборов контейнеров сведены в одну — внешне ничего не изменилось (0.99.0);
- версия `0.99.0` синхронизирована во всех пользовательских точках;
- симуляция, баланс и формат сохранений при этом не менялись.

Подробности — в [`docs/CHANGELOG.md`](./docs/CHANGELOG.md).

## Почему стоит заглянуть в исходники

TERRA 2136 показывает не только результат, но и инженерный процесс вокруг игры:

- **Детерминированность:** бой работает на фиксированном шаге 20 Гц и сидировании, поэтому логику можно воспроизводить и проверять.
- **Безопасная прогрессия:** кошелёк и награды проходят через транзакционный слой `TerraProgress`, а не начисляются UI напрямую.
- **Офлайн-first:** финальный продукт — автономный HTML без сетевых запросов и runtime-зависимостей.
- **Модульная разработка:** markup, CSS, UI, симуляция, рендер, engine и data редактируются отдельно, а затем собираются инструментами проекта.
- **QA как часть разработки:** после изменений проверяются синтаксис, навигация, мобильные разрешения и smoke-тест боя.

Проект будет интересен игрокам, разработчикам браузерных игр, UI/UX-инженерам и тем, кто хочет увидеть путь от прототипа к аккуратному playable-артефакту.

- Python 3.11+
- Node.js 20+

## Сборка и проверка

### Собрать игру

```bash
python3 tools/build.py parts/ dist/TERRA2136_PLAY.html
```

### Разделить готовый HTML на исходники

```bash
python3 tools/split.py TERRA2136_PLAY_v0.99.0.html parts/
```

### Проверить синтаксис

```bash
python3 tools/check.py dist/TERRA2136_PLAY.html
```

### Запустить QA

```bash
python3 -m pip install playwright
python3 -m playwright install chromium

python3 qa/qa.py dist/TERRA2136_PLAY.html --out qa-out --no-battle
python3 qa/qa.py dist/TERRA2136_PLAY.html --out qa-out --battle-only --viewports mobile
```

Финальный результат тестов выводится как `QA RESULT: PASS` или `QA RESULT: FAIL`; подробности и скриншоты сохраняются в `qa-out/`.

## Для портфолио

TERRA 2136 удобно смотреть как на законченный вертикальный срез продукта: у проекта есть игра, публичный вход, адаптивный интерфейс, локальная прогрессия, рендеринг, сборка и автоматическая проверка качества.

Это пример того, как превратить большой браузерный прототип в понятную систему:

- пользователь может сразу открыть и проверить результат;
- исходники организованы по ответственности;
- визуальные и продуктовые изменения фиксируются по версиям;
- инженерные инварианты защищают симуляцию, сохранения и баланс;
- README, roadmap, changelog и QA являются частью продукта, а не приложением к нему.
